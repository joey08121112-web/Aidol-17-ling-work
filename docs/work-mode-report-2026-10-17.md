## 一、本轮目标

让工作模式接近飞书妙记的体验：说话时屏幕实时出字并标出说话人；每句有时间；结束后有带依据的 AI 纪要、章节和重点；可以回听，也可以保存为文件。

## 二、已完成的功能

| 方面 | 内容 |
| --- | --- |
| 实时字幕 | 新增 `WS /v1/work-meetings/{id}/live`。录音时 PCM 流式送到火山流式 ASR 2.0，灰字为正在识别，变黑表示服务器已保存为带时间的句子 |
| 说话人 | 开启火山说话人聚类，句子标为“说话人 1 / 说话人 2”，纪要也能看到这个标签。按声音自动分组，不识别真实身份 |
| 时间 | 每句有录音内时长（00:00:41）和本地时刻（到秒；以录音起点为基准，自动扣除暂停）。会议有日期、星期和起止时间 |
| 文字记录样式 | 采用飞书“文字记录”样式：左侧细线的信息块（主题、录音时间、时长、说话人），正文按说话人分段，段首为“说话人 1  00:00:41”。对话页的工作模式、工作页字幕和会议详情页统一使用这一样式；对话页下拉可看到实时内容或最近一场会议 |
| 录音保存与回放 | 录音按账号保存，默认 30 天，可设为不保存，到期自动删除。全屏会议页底部有常驻播放条，支持拖动进度；点击句子、章节、依据或标记，会从对应位置播放并高亮当前句 |
| 录音控制 | 支持暂停/继续（暂停期间不记录、不上传）。手机按钮和耳机双击都能标记重点，耳机双击只在录音中生效；工作模式只在待机时才能双击切换模式 |
| AI 纪要 | 摘要、智能章节（服务器计算时间）、关键决策、待办（负责人或截止时间不明确时标为“未明确”）、逐字摘录的重点原话、待确认事项；每条都有可跳转的原文依据 |
| 分段与兜底 | 20 秒分段在字幕已覆盖时只存录音，不重复识别，也不占额度；字幕中断的那一段由服务器整段识别，并替换该段内的字幕句子 |
| 保存为文件 | 会议页可导出 Markdown 文件，内容包括日期时间、说话人、摘要、章节、决策、待办、重点和带时间的原文 |

## 三、本轮发现并修复的问题

1. 注册时遇到 409（账号已存在），界面一直显示“正在连接…”，看不到原因。已改为直接显示服务器的提示。
2. 本机另一个项目的服务（`Aidol-17-life-p0`）也占用 8108 端口，会被自动拉起，并导致本仓库后端被终止，手机请求落到错误的服务器上（登录失效、开始记录失败）。已为启动脚本新增 `--port` 选项。本地开发现在用 `--port 8118`，并执行 `adb reverse tcp:8108 tcp:8118`。
3. 火山流式识别会把多句话合成一条返回。已改为按标点拆句，有逐字时间时用逐字时间，没有时按字数估算。

## 五、尚未验证 / 已知问题

- 两人及以上真实会议中，说话人区分是否准确；暂停或连续录满 10 分钟换段后，说话人编号可能错位。
- 长时间会议中流式识别是否稳定、字幕延迟多少、断网时兜底识别是否顺畅；本地时刻约有 1–2 秒误差。
- 耳机 SDK 有时陷入“连接→序列号/绑定码校验 2 秒超时→断开”的循环（日志为 `SN check err, disconnect`）。根因未查明，需要用户重新配对后复测，或向厂商确认绑定码规则。
- 录音以原始 PCM 存储，约每小时 115 MB；部署时的备份尚未覆盖录音目录。

## 六、与主分支的合并状态

`origin/main` 在 21:49 新增了 `7144386`（jun0315：整场录音结束后用千问 filetrans 识别全场说话人，并做整场一次性总结）。它与本分支实现的是同一功能，但设计不同：

- 录音中：对方只上传录音，不显示实时文字；本分支有实时字幕。
- 说话人：对方在结束后识别整场，编号全程一致；本分支在录音中流式识别，编号可能在暂停后错位。
- 录音：对方转写后即删除，最多保留 24 小时；本分支默认保留 30 天用于回放。
- 总结：对方新增各人物观点、冲突和事件；本分支新增章节和重点原话。
