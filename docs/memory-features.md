# Android 记忆、会议纪要与行动项

Android 的“记忆”和“工作”页面使用当前登录后端中属于该账号的 SQLite 数据。切换本地电脑服务与远端服务不会同步内容；拉取源码也不会取得其他人的记录。文字模型复用后端 `TEXT_API_KEY/TEXT_BASE_URL/TEXT_MODEL`，无需额外注册记忆平台。模型不可用时按接口返回规则或摘录来源，不能把降级结果描述为模型成功。

## 工作记录与纪要

1. 切换工作模式，主动分段录音或发送文字。工作模式不播放回复；需要保留转写才能在后续整理工作记录。
2. 在“工作”页点击“生成会议纪要”，选择最近 1 小时、24 小时或 7 天。
3. 核对摘要、结论和来源。没有明确依据的负责人和截止时间保持未知，不根据通用“用户”标签猜真实姓名。
4. 在行动清单设置完成或待完成；状态存入当前账号，重新登录仍保留。
5. “复制纪要”只复制文本，不发送消息，也不创建外部日历事项。

当前整理的是时段内的工作记录，没有独立会议 ID 或自动会议边界。后端从最近最多 1000 条转写中选时段内最多 80 条工作发言；模型输入另限单条 2000 字、总量 18000 字，不能保证覆盖时段全部对话。同一输入快照复用报告，不同快照可能产生相似任务，需要人工核对；当前页面显示最新纪要，导出可包含历史报告。

普通记忆的“待办”类型只是线索，没有完成状态。只有行动项表中的 `open/done` 能表示用户标记是否完成；生成纪要并不代表任务已经执行。

## 问记忆

在“记忆”页的“问问你的记忆”输入问题，点击“检索记忆”。后端从自己的有界记忆、转写和行动项中选择相关原文，返回回答与引用；没有足够证据会说明不足。

引用 ID 和摘录子串经过校验，防止凭空拼造出处；这不保证每条命中都最相关，仍需核对。“未完成待办”使用行动项真实状态，不能根据一段旧承诺推断今天仍未完成。行动项证据包含结构化负责人、截止和状态，属于待办记录，不是录音逐字原话。当前不提供无限历史或向量语义检索。

## 保存、编辑和来源

- “+ 新记忆”：输入内容并选择偏好、事实、待办或出行，保存为用户笔记，不依赖额外模型。
- 对话中的保存记忆动作：将指定转写完整原句存为事实笔记，并以 `transcript:{id}` 关联来源。重复保存复用同一笔记，保留后续编辑和置顶。
- “置顶” / “取消置顶”：置顶记录优先显示；置顶表示用户重视，不证明内容真实。
- “编辑”：修改内容或分类，保留创建时间和来源，不改写原始转写，也不会自动重算旧纪要或行动项。
- “原文”：只对明确关联的转写笔记展示精确来源；自动提取记录只有提取方式时，不能猜一段相似文字替代原话。
- 分类按钮只筛选当前快照，列表最多 300 条记忆、100 条转写、300 条行动项；不能把未显示解释为数据库从未保存。

## 导出、清空与隐私

“我的”提供 v3 JSON 导出，包含账号、设置、记忆、转写、纪要、行动项和草稿，各集合最多 10000 条；当前没有导入接口。清空需要密码，删除业务记录与幂等结果，保留账号和设置；注销账号会另行删除在线身份及用户业务库。执行前先停止录音，按需导出。历史备份按 [部署文档](android-deployment.md) 管理。

`retain_transcripts=false` 只阻止新增转写历史，不删除旧记录，也不关闭记忆提取或幂等结果保存。记录中的文字始终是用户数据，不因包含“执行命令”等表达而获得指令权限。

硬件输入来源、实际听音与模型效果的真实证据见 [验收记录](acceptance.md)。这些功能不依赖耳机物理按键，也不表示支持离线采音或全天后台监听。完整字段、上限与错误语义见 [API 契约](api.md)。
