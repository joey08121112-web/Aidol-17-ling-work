# 安卓操作提示音

2026-10-18 按用户要求，App 内24段固定中文操作语音全部替换为无语音耳标。随后按用户反馈，三个模式改为音量更明显的双声，其他操作保持单声。文字状态保留；正常 AI 问答、用户主动朗读和会议录音回放保持原样。本页覆盖历史文档中“播报模式名称 / 开始录音 / 录音结束”的说明。

## 固定声音

| 场景 | 固定耳标 | 总时长 |
| --- | --- | --- |
| 生活模式 | 两声清亮，659→698 Hz轻微上扬 | 765 ms |
| 工作模式 | 两声低柔，440 Hz稳定音高 | 725 ms |
| 通勤模式 | 两声轻扬，784→880 Hz | 805 ms |
| 其他已有操作提示 | 统一柔和确认音，587→554 Hz | 280 ms |

模式提示为两声相同的连续音符，中间85ms静音，每声保持35ms圆滑起音、140ms尾部淡出和低比例谐波；模式振幅系数由0.13提高到0.53348（约+12.26dB，包含用户追加的+5dB），不调整手机系统音量。其他操作仍为原来的单声，资源逐字节保持不变。无随机选音、无拼接语音。三个模式与资源一一固定映射，通勤页“开始通勤”若实际改变模式，同样使用通勤耳标。

原来静默的定位更新、会议纪要导出和录音中标记继续静默；不为所有页面动作新增声音。耳机连接的App文字小弹窗保留，已有佩戴/设备等操作音统一换成确认耳标。耳机固件自身发出的连接语音由设备控制，当前Rise SDK没有本项目已核验的关闭/替换接口，本次未修改固件。

## 播放与互斥

- 模式设置先由后端确认成功，再播放本地固定耳标；失败不撤销已生效模式，也不自动开始收音。快速再次切换会取消旧提示，沿用原有组合判定和防抖。
- 其他操作提示由 `QuickFeedback` 沿用节流和录音/通话/回放互斥，连续点击不累积播放队列。完整操作说明仍以页面文字为准。
- 现有会话开始使用70ms本地耳标，连续问答后续轮次不重复播放。工作录音及结束保存流程保持原有逻辑；此前没有启用的START/END资源不因本次替换被重新启用。
- `ReplyPlayer` 继续核验连接Rise的实际输出，不回落手机扬声器。模式耳标沿用 `PlaybackLease`，等待旧采集清理后再播放；不与录音同时开启。
- 不调用系统TTS或后端合成，不改变正常AI回答音频及来电录音处理。

## 来源与维护

音频为本地数学合成的24kHz、PCM16小端、单声道WAV，所有平台使用同一套已提交产品资源。`scripts/android_cues.json` 的 labels 只作显示/说明，不参与合成；tones定义固定音高与时长。

```sh
python scripts/generate_android_cues.py
```

Windows原 `generate_android_cues.ps1` 仅包装上述Python脚本，不再使用System.Speech或中文语音包。生成不需要网络。标准构建无需重新生成。

单测逐一核对资源可复现、短时长、首尾静音、峰值/相邻样本跳变、两段可听区间、模式响度提升、三模式互异及其他操作同音。可用 `-PaidolEarconReview` 构建并运行 `com.aidol.demo.EarconInstrumentation`，在真实耳机上验证三模式与通用提示播放、输出设备、零开麦和零测试API请求。实际结果见[验收记录](acceptance.md)；输出链路通过不等同于用户对听感的主观确认。
