## 2026-10-17 操作反馈改为短语音

Android 自有 Toast 已移除。复制、导出、权限和设置检查等使用打包的离线短语音，完整说明保留在页面或当前自定义弹窗内；模式切换沿用一次本地模式播报，不再同时弹 Toast。模式提示播放中可再次点击模式或双击耳机，停止旧提示并提交新模式，成功后播新提示，无需等旧提示结束；自然播完也不会丢失正在判定的双击。普通短提示在180ms 内连续点击只保留最后一个待播提示，播报中不排队，相同提示四秒内不重复。提示仅通过核验的 Rise 耳机媒体输出播放，不调用服务器。

录音、AI 回答和连续会话期间不插播操作提示；新会话开始、离开前台、来电、断连或双耳确认摘下时停止待播/正在播放的提示。耳机不可用时仍可看文字，不回退手机外放。系统剪贴板等 Android 自带提示不受 App 控制。确认删除、重新登录等必要对话框保留。

## 2026-10-17 AI 通话重构（当前源码）

默认音频唯一为 **Rise SDK 麦克风**，已移除系统蓝牙/模拟器采集实现；旧音频偏好统一迁移为 Rise。debug、release 的新安装均默认 **本地电脑服务 `http://127.0.0.1:8108`**，手机通过 USB reverse 访问。已明确选择的远端服务保留；可在登录页或“我的 → 连接设置”切换。所有构建的登录凭证按精确服务源隔离，旧 release 的通用凭证不跨源复制，首次升级可能需要重新登录。只对精确回环地址开放 HTTP，远端仍验证 HTTPS。

主按钮默认“接通 AI”。生活、工作、通勤的默认通话都使用 `continuous_call`：停顿约 600ms 后静默处理，明确叫助手提问或切换模式才回应；本段结束约 180ms 后准备下一轮，不必反复点击。单击可提前发送，回复时单击停止播报并接续；长按或手机“挂断”停止通话。打断后已提交的业务仍完成一次，再进入下一轮，不重放录音。安静时持续待命直到用户挂断；底层每45秒无声片段轮换采集，不生成业务、不连接ASR、不消耗语音请求额度。检测到人声后才连接ASR，保留320ms前缀避免吞首字。当前是交替收听/播报，**没有全双工同时说话或语音自动抢话**；停句是能量检测，不是神经网络 VAD。

先准备耳机收音，检测到人声时建立 WebSocket，握手期间有界缓存首段语音。通话开场只播放约70ms短提示，不再每轮播读“开始/结束录音”；接续轮不重复开场提示。服务能力 `voice_reply_stream` 开启时，ASR 与录音并行，回复 PCM 通过同一条鉴权 WebSocket 流式播放，TTS 与记忆提取并行；业务结果落库后才发送最终 `result`。**文本模型目前仍返回完整文本，再开始 TTS，不是 token 到语音的全链路流式**。常态对话需要支持 `continuous_call` 的新版后端；没有流式能力时使用同来源的普通上传接口。

支持通知时，主动接通 AI 会建立有通知的锁屏会话；首次通知授权与录音权限一起申请，拒绝通知仍可在前台通话。通话持续续期，只有结束后的待命一小时到期，可从通知停止；来电、断连、双耳确认摘下、Activity 销毁停止，重连不自动开麦。定时和安静记录仍只在前台运行。工作页“开始记录”切到独立的安静记录；记录中单击先收尾当前记录，再进入 AI 通话提问。

记忆显式问回保留原文引用；通用对话增加 `recall_memory` 本地只读工具，支持模型主动查当前账号历史。普通“我该怎么办”不再仅因包含“我”就被强制送入记忆检索。模型回答通常一到三句、80字以内。找不到依据应说明未找到，不将问题或模型推测保存为事实。

本节优先于下文历史说明；测试结果和真机观察见 [验收记录](acceptance.md)。

## 2026-10-17 语音记忆与显式锁屏会话

本节描述本次新源码/debug 构建；下文旧发布包、哈希和历史实机记录保持原版本含义。应同时更新本地后端和 Android，新增协议见 [API](api.md)。

1. 先登录并连接耳机；Rise 模式需实际连接/触控监听就绪。对话页展开“聆听方式”，选择“开启本次锁屏耳机会话”，授予录音与通知权限并保持通知可用。
2. 手动短语音说“记住，我答应客户周四交方案”，应明确返回已保存记忆、尚未建立提醒。工作模式手动提问现在可回应；连续/定时工作采集仍只记录。
3. 开启锁屏会话后锁屏，触控单击提问“我答应客户什么时候交方案”，再说“后来改成周五了”、再次问回、“忘记刚才那条”、最后问回应无依据。手机“查看最近回答依据”可核对原文和记录时间；更正/遗忘后旧证据立即撤回。
4. 通知中的“停止会话”结束本次授权。最长一小时；关闭任务、Activity 销毁、通话、Rise 断连后需重新开启。系统回收不自动恢复。服务不在后台接续连续或定时录音；系统蓝牙路径不新增未经验证的触控入口。
5. 双击切模式在当前轮次完成后生效，不丢弃正在录的片段；单击发送与长按取消保持原映射。失败时“查询上次请求结果”只读恢复状态，不会再次上传、执行工具或自动朗读。

语音更正/遗忘仅处理十分钟内唯一记忆；有多个候选、混合会议任务或只有转写时，需要先明确对象。任务完成仍在工作页操作，记忆保存不等于闹钟或位置提醒。遗忘范围含该记忆及明确关联原文/派生记录，独立记录和运维备份另行处理；不是全账号清空。

本次已通过离线单测、lint 和构建，USB 无设备，以上操作顺序是**待执行验收脚本**，不是成功的实机观察。请分别验收锁屏短语音、通知停止、双击保片段、佩戴→未知→摘下、来电/断连与音频路由；不得由构建成功推断手机放口袋可稳定使用。

## 常见情况

账号已存在时换一个账号名；忘记密码使用恢复码。登录失效可能因为会话到期、另一设备改密/找回、或超过五个会话被淘汰。退出不会删除服务器数据。

无声时先看文字是否已经生成，再检查手机媒体音量、耳机媒体音频开关及 App 显示的实际输出。不要把“已生成 TTS”当作实际听见。当前构建是否可听见仍需本轮真机反馈；工作模式本来就不主动播放。

“上一项操作仍在进行”表示当前账号正在处理录音或其他操作，稍等再试。网络超时后先看历史记录，避免盲目重新发送。每账号默认 24 小时窗口 300 次服务操作，聊天/识别与语音合成分别计数，地图、检索和纪要也计数；这不是 300 次完整语音对话。

“服务不可用”或证书问题请记录时间、App 版本和错误提示交给负责人，不在手机填其他 API Key，也不要关闭证书校验。登录与业务始终走 HTTPS IP。

- 仅已主动开始的工作会议启用此策略。工作 SDK 采音不申请 Android 播放音频焦点，不切换 SCO，不暂停音乐；生活/通勤原有来电中断逻辑不变。

- 通话双方 PCM 按场景内采样位置合并成 16kHz PCM16 单声道，使用两秒有界缓冲和 250ms 单路等待；缺失一路时以静音补齐该路，迟到样本不重复延长时间轴。仅收到两路数据后显示“已收到双方音频”；这不代表人声内容已由 ASR 确认。SDK 未提供逐包时间戳，双路同步及回声表现需要真实通话验收。
- 来电对话保存在当前会议，时间轴新增“开始记录电话对话 / 电话对话记录结束”。挂断并退出 SDK 通话场景后恢复原工作记录；手动暂停保持暂停，用户结束后不再自动开启。断连、双耳摘下、关闭 App 等原有停止条件保留。
- 开始工作录音会建立持续通知与前台服务，需要通知权限；打开音乐播放器、接听界面或锁屏不会仅因 Activity 离开前台而结束录音。通知“停止会话”会排空并保存工作记录，工作录音自动申请的服务随本次录音完成而结束。定位仍仅在 App 前台每 180 秒更新，不新增定位弹窗或后台定位。

## 2026-10-18 熄屏会议定位缓存

`ForegroundLocationMonitor` 和手动定位在上传前写入 `MeetingLocationCache`，采用私有 SharedPreferences，按服务和登录会话隔离，保留实际获取时间；账号退出/清空/切换服务清理。`LocationSnapshot` 校验24小时有效期及200米精度。`HostedSession` 通过 Activity 可见状态及系统亮屏/锁定状态限制 `MeetingStartLocation`：前台可最多等待3秒新定位，后台只读App/系统缓存，缺失不阻塞录音。前台180秒刷新、无定位弹窗、地址失败30秒×3次重试均保留。

会议快照追加 `observed_at/cached`，后端解析地址与生成报告保留元数据，页面与Markdown导出明确显示缓存获取时间。验收 runner 使用 `-PaidolLocationCacheReview` 构建，`LocationCacheInstrumentation` 的 `phase=seed/verify` 分两次进程运行；仅独立测试命名空间私有存储和公开测试坐标，不写用户会议，不调用真实地图或模型。实际结果见 acceptance.md。


## 2026-10-18 通勤地址与锁屏刷新（本地）

`CommutePanel` 接管通勤页和“我的 → 账号与隐私 → 常用地址”。支持家、公司、学校和多个自定义地点；地址解析一次保存坐标，名字/标签单独修改不解析。城市/详细地址修改会使旧坐标失效，确认新结果后才能保存。起点可选手机当前位置、常用地址或搜索地址，目的地同样可选；固定起点路线始终使用选定地址，界面明确标为耗时估算。

新增弹窗统一使用 `EditorUi` / `RoundedChoiceDialog`：圆角边框、选中强调、进入和选择动画；局部更新路线卡片，保存/关闭弹窗不重建底层页面。地址、路线、天气、附近地点、出行方式及到达提醒共用该样式。位置更新沿用无弹窗策略。

用户明确选择“开始通勤后锁屏也继续更新”。`CommuteService` 为独立 location 类型前台服务，必须由可见 Activity 在定位和通知授权后启动，保持“通勤进行中”通知及“结束通勤”动作。后台每180秒读取手机定位、记录并更新路线；GPS路线只接受近期准确点，失败显示状态并重试，不把旧会议缓存冒充当前位置。使用有超时并定期续期的部分唤醒锁，结束释放定位监听、网络请求和唤醒锁。服务 START_NOT_STICKY，被强制关闭或进程终止后不会偷偷重启，重新进入明确显示“继续通勤”。仅在本次通勤运行期间扩展后台定位；未开始通勤时保留原有仅前台3分钟刷新，会议缓存行为不变。

通勤不申请音频焦点、不打开麦克风、不改动 Rise 协议。启动时拒绝正在进行的工作采音；切换非通勤模式、退出账号、清空数据、切换服务器和通知结束均停止。服务按服务器/账号会话隔离；离线结束先停本机，队列下次联网补发；旧路线结果不能恢复已结束旅程。Activity仅销毁/切后台不会结束主动通勤。

官方约束参考：[位置前台服务](https://developer.android.com/about/versions/14/changes/fgs-types-required)、[位置授权](https://developer.android.com/develop/sensors-and-location/location/permissions)。当前从可见页面启动持续定位服务，不请求“始终允许”位置授权；系统强制停止、撤销授权或厂商省电仍可能中断，界面保留恢复入口。
