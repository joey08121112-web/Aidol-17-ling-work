# Android 角色动画与验收约定

本约定说明角色视频如何表现已有的模式和会话阶段，不新增录音、休眠、打断或业务能力。模式与通话规则以 [三模式约定](mode-experience.md) 和 [API](api.md) 为准；实际执行结果另记入 [验收记录](acceptance.md)。本文中的验收场景是待执行步骤，不表示本轮测试、供应商链路或物理耳机已经通过。

## 素材与职责

统一使用 `CompanionAvatarView` 展示透明角色，由纯 Java 的 `CompanionPhase` 表达阶段。角色直接融入页面，不显示素材白底、方形容器或装饰外圈。阶段来自会话、采音、实际播放及会议状态；视频播放进度不能启动麦克风、提交内容、改变模式或决定通话是否结束。

| 素材代号 | 用途 | 边界 |
| --- | --- | --- |
| A | 生活陪伴；工作清醒、稳定的记录形象；`companion_life_loop` | 工作录音中保持记录语义，不表演正在回答 |
| B | 通勤行走形象；`companion_commute_loop` | 行走是模式视觉，不表示定位、导航或路线刷新成功 |
| C | 储备素材，当前不接入界面 | 不通过隐藏操作自动启用 |
| D | 语音会话实际停止后的 `RESTING` 收尾，`companion_rest_once` 播放一次，随后保持结束静帧 | 不作为开屏默认状态，不在已接通静默、工作暂停或处理失败时睡去；主动新操作或切模式才离开结束静帧 |

资源使用本地无音轨视频，角色播放器保持静音，不申请音频焦点。`companion_life_poster`、`companion_commute_poster` 和 `companion_rest_poster` 是带透明通道的 WebP，用于首帧/失败回退；`companion_rest_end` 提供 D 的透明结束静帧。视频解码或首帧失败时显示稳定的回退画面和正常状态文字，不影响耳机采集、播报、停止操作。输入与输出使用角色下方的轻量音量柱，连接和处理使用状态点，配合阶段文字；不再绘制环绕角色的外圈。

打包视频为 960×480 的 H.264 双半幅：左侧 480×480 为 RGB，右侧 480×480 为灰度透明度。`AlphaVideoRenderer` 通过原生 EGL / OpenGL ES 2.0 从同一帧取两侧数据，输出预乘透明色到透明 `TextureView`，最终可见画面仍为正方形角色。不能将整张双半幅画面直接交给普通视频 View 显示。播放器仅接受准确的 960×480 格式，尺寸不符时直接使用透明海报，避免把普通视频或旧资源的左右半幅误当角色和透明度。A/B 处理首尾衔接；替换 D 时同步更新 `CompanionVisualPolicy.REST_DURATION_MILLIS`，否则页面恢复可能提前或延迟切到末帧。A 的静帧选用睁眼稳定姿态，供工作、错误和停止中使用。

本轮最终编码规格如下，时长按帧数与帧率计算并保留三位小数：

| 视频资源 | 帧率 | 帧数 | 时长 | 文件大小（字节） |
| --- | --- | --- | --- | --- |
| A · `companion_life_loop.mp4` | 24 fps | 92 | 3.833 秒 | 629,365 |
| B · `companion_commute_loop.mp4` | 24 fps | 120 | 5.000 秒 | 1,259,382 |
| D · `companion_rest_once.mp4` | 24 fps | 145 | 6.042 秒 | 956,107 |

三段无音轨视频共 2,844,854 字节；四张 480×480 透明 WebP 共 321,784 字节，以上角色资源合计 3,166,638 字节（约 3.02 MiB）。D 的阶段恢复时长取整为 6,042 毫秒，与 `REST_DURATION_MILLIS` 一致。

生活和通勤共用固定顶部模式选择、可滚动聊天记录、底部透明角色及输入/通话按钮。设置入口与模式选择同行，保留 48 dp 点击区域；关闭历史记录时才显示一行简短说明。生活与通勤采用相同角色容器尺寸、位置与构图基线，切换模式时保留草稿、焦点和滚动位置。键盘展开时隐藏角色和辅助文案，发送及结束通话仍可操作。工作页与对话页的工作模式将角色缩小放在说明旁，主要空间留给录音控制、时长、字幕和会议记录。

## 阶段语义

| `CompanionPhase` | 界面含义 | 进入或退出依据 |
| --- | --- | --- |
| `IDLE` | 未接通，等待用户主动开始 | 初始页面、模式切换后的待机；预连接 `prepared` 不算开麦 |
| `CONNECTING` | 正在连接或准备设备 | 用户已主动开始，采音尚未真正启动 |
| `LISTENING` | 已接通，正在听或等待下一句 | 本次采音已启动；已接纳的 `input.speech_start`；回复实际播完且本次通话仍存活 |
| `THINKING` | 正在处理当前问题 | 会话处理事件；正式回答以 `thinking` 为准，不能由无关状态文案猜测 |
| `SPEAKING` | 正在实际播放 AI 回复 | 回复 PCM 开始实际播放后进入；播放排空、打断、停止或播放失败后退出 |
| `RECORDING` | 工作会议正在记录 | 工作采音已启动且未暂停；分段上传与字幕更新不改变此主阶段 |
| `PAUSED` | 本场工作录音已暂停 | 本机已暂停采集消费，不再缓存或上传暂停期间的 PCM；继续后回 `RECORDING` |
| `SAVING` | 已停止，正在排空并保存会议 | 停止工作录音后等待尾段、上传与会议结束回执 |
| `SUMMARIZING` | 录音保存后正在整理会议 | 当前会议的 `summary_status` / `summary_stage` 表明后台整理中 |
| `COMPLETE` | 当前操作已有成功回执 | 按操作区分原文保存与 AI 整理完成；不能把 `partial/empty/fallback/failed` 当完整成功 |
| `STOPPING` | 正在结束语音会话 | 主动停止后保持清醒静帧；异步采音清理尚未确认完成，不能直接睡去 |
| `RESTING` | 已结束语音会话的短暂收尾 | 会话实际停止后播放 D 一次，保持结束静帧至主动新操作或切模式；不循环睡眠 |
| `ERROR` | 当前操作或设备出现异常 | 会话、采集、播放或保存的明确失败；保留可理解的错误文字 |

`reply.start` 可以先于可播放音频到达，`reply.text` 只是文字快照，`reply.done` 只是生成完成，`result` 只是业务结果。它们均不能单独证明正在发声或已经播完。回复结束应等待 `ReplyPlayer` 排空；连续通话继续使用原有 `playback.done(turn)` 确认。

生活和通勤接通后静默不挂断。播报时普通背景声音不触发切换；“小万”打断时应立即停止说话表现并回到接纳输入的状态，不能等待视频循环边界。只说“小万”而没有新问题时保持聆听，不能永久停在思考。一次回复失败不必然意味着整场通话终止，必须按实际会话状态决定后续显示。

`HostedSession.cancel()` 的清理是异步的。主动结束先进入 `STOPPING`，确认耳机控制器已释放采音后才进入 `RESTING`；该只读确认要求设备仍就绪、没有采音所有者且 SDK 不再忙。停止超时或设备断连进入 `ERROR`，不能仅因发出了取消请求而表现为已经睡去。

工作录音的字幕 `partial/final`、每 20 秒分段提交及后台处理不会把主角色从 `RECORDING` 切成 `THINKING`。结束后原文保存与纪要整理分开显示：原文成功、纪要失败时保留原文成功事实，同时明确整理失败；不显示完整整理成功或睡眠来掩盖失败。

## 生命周期与竞争处理

- 只在页面和窗口可见时解码、渲染；切页、退后台、锁屏、销毁或视频 Surface 失效时停止并释放播放器。回到页面根据最新阶段恢复，不继续已失效的过场。
- 所有 UI 状态在主线程更新。会话代次、回复轮次与播放器实例用于隔离旧回调，旧回复排空不得覆盖新一轮思考或新会话连接。
- 重复设置同一模式和阶段不重建播放器，不因音量或字幕频繁更新反复 seek、闪黑或从头播放。
- `phaseStartedAtUptime` 保留当前阶段的原始进入时刻。页面重建或显示恢复按该时刻还原 D 的进度或结束静帧，不能把同一次 `RESTING` 当成新收尾再播放。
- 使用相同构图和裁切，素材切换期间保留已有画面或明确回退画面；错误、打断和停止立即生效，不受视频剩余时长阻塞。
- 透明海报不能遮住旧角色帧。切换时先隐藏旧视频层，只有通过格式校验、仍属当前 `generation` 且页面可见的实际首帧才能替换海报；旧 EGL Surface 完成释放后才创建新的渲染器，不能让两个渲染器同时占用同一输出 Surface。
- 海报与视频在同一 UI 帧切换，不做交叉淡化，避免恢复播放时海报与视频的不同姿势叠出双脸、双手。`ImageView` 的透明度使用浮点 `setAlpha(0f/1f)`，不得误用旧的整数透明度重载。
- 角色状态不覆盖原有按钮文案、录音时长、会议进度与错误提示；无障碍描述使用实际阶段。角色视频没有声音，不能借此判定耳机已经正确播报。
- 显示与会话生命周期分别管理：页面隐藏需要停止视频渲染，是否停止业务仍由既有会话规则决定；不能由角色 View 自行停止或重新开始录音。

## 可执行验收场景

使用 USB 安卓真机和同一 `/auth/*`、`/v1/*` 后端。需要供应商调用的场景应主动执行并记录，不加入自动供应商探测。每项同时核对角色、文字、按钮和真实业务状态。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 初始与模式切换 | 启动；依次选生活、工作、通勤 | 全部为未开麦 `IDLE`；A/A/B 对应正确；没有默认睡眠或自动开始 |
| 透明嵌入与对齐 | 等海报切换后观察生活/通勤视频；切到工作浅蓝卡片；反复切模式 | 无白色方块、残余圆框、白边、脸部透明孔、双影或上下翻转；生活/通勤容器和基线一致，工作角色不挤压主要操作 |
| 紧凑屏幕与输入 | 在窄屏、长消息、系统键盘展开/关闭时检查生活及通勤 | 模式和设置同行不重叠；聊天区可滚动；键盘展开后发送/停止可达；草稿、焦点和位置不因生活/通勤切换丢失 |
| 预连接 | 等待预连接完成，不点击开始 | 保持待机；没有“正在听”、开麦或 D 收尾 |
| 连接较慢或失败 | 主动开始，在连接完成前观察；用不可用网络重复 | 先 `CONNECTING`；真实采音开始才聆听；失败显示 `ERROR` 及原因 |
| 连续对话 | 生活、通勤分别说话并等待回答 | 听取 → 思考 → 实际播放时说话 → 播放排空后聆听；没有每轮结束睡眠 |
| 文字先到 | 让文本先于 PCM，或使用受控回调驱动 | 只有文字/`reply.start` 时不假装发声；PCM 实际开始播放后才 `SPEAKING` |
| 音频仍未排空 | 生成结束时仍有播放缓冲 | `reply.done/result` 不提前回聆听；声音播完后才切换 |
| 静默 | 接通后静默至少 60 秒，再继续说话 | 仍保持已接通聆听；无自动睡眠、挂断或重新开麦 |
| 语音打断 | 播报时说普通话语，再说“小万”；单独只说“小万”再试 | 普通声音不打断；关键词立即清除旧播放并切阶段；只说关键词后继续聆听 |
| 主动结束 | 播报中和聆听中分别单击结束 | 清理中先 `STOPPING`；采音释放确认后 D 收尾至多一次并保持末帧；无旧回调重启 |
| 停止未完成 | 延迟 SDK 停止确认，或停止期间断连 | 保持清醒的 `STOPPING`；超时或断连显示 `ERROR`，不提前播放 D |
| 快速结束与重开 | 结束后立即再次开始或切换模式 | 新 `CONNECTING/IDLE` 优先；旧 D 完成、旧播放排空和旧结果不覆盖新状态 |
| 工作持续记录 | 录音超过 45 秒，观察字幕和至少两个分段上传 | 保持 `RECORDING`；无随上传闪烁的思考/说话；字幕和时长继续增长 |
| 工作暂停继续 | 录音中暂停、说话、继续 | 暂停显示 `PAUSED`，不睡去；暂停期间不缓存或上传；继续后恢复记录 |
| 工作结束整理 | 正常结束有讲话的会议 | 排空时 `SAVING`，整理时 `SUMMARIZING`，成功回执后完成；阶段文案匹配真实进度 |
| 工作不完整 | 模拟缺段、无讲话、字幕中断和纪要失败 | 不误报完整成功；字幕失败但录音仍在继续时保持记录并提示降级；原文与整理结果分别显示 |
| 设备断开 | 录音/播报中断开 Rise 耳机 | 执行既有停止和错误流程，显示错误；不伪装用户结束或睡眠 |
| 页面生命周期 | 反复切页、锁屏、退后台、回前台；销毁重建界面；视频首帧前快速切模式 | 隐藏时不持续解码；回到当前状态；无黑屏、残留旧帧、重复 EGL 输出 Surface、资源泄漏或自动开麦 |
| 视频失败回退 | 用受控错误、缺失资源或非 960×480 旧视频测试角色播放器 | 使用稳定的透明海报，不暴露错误半幅；状态可读，开始/停止、字幕和耳机音频仍正常 |
| 音频互不干扰 | 比较显示角色前后提示音、采音、回复和路由 | 视频无声、不抢焦点、不改变路由；真实耳机听音单独记录 |

自动验证优先覆盖纯阶段映射、重复状态、旧轮次回调、播放开始/排空、失败与恢复、`RESTING` 单次完成。`python -m pytest tests/test_android_companion_assets.py -q` 校验三段 MP4 的 H.264 编码、960×480 尺寸和无音轨，以及四张 WebP 的 480×480 尺寸和透明通道；这些文件结构检查不能证明人物边缘或实际合成画面正确。构建按仓库要求执行 `testDebugUnitTest lintDebug assembleDebug`。视觉检查需涵盖紧凑手机、长文字及页面恢复，并捕捉海报切换后的实际透明视频帧；静态海报正确不能证明 EGL 视频方向、透明度与边缘正确。构建与模拟回调不证明物理耳机听音、插话延迟、功耗或持续录音正确。

动画视觉验收构建同时使用 `-PaidolVisualReview -PaidolAvatarReview`，应用 ID 为独立的 `com.aidol.app.avatartest`，通过测试 instrumentation 启动；它不带桌面 launcher 图标，避免被误当日常 App 打开。此测试构建及截图不代表生产账号、供应商语音、物理耳机或全片素材已通过验收，实际执行范围与结果仍以 [验收记录](acceptance.md) 为准。
