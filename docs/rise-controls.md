# Rise 耳机联动

本功能使用官方 SDK 6.7、安卓真机与 Rise SDK 麦克风。当前以 [三模式约定](mode-experience.md) 为准：单击开始/结束整场，双击结束并切换且目标待机。生活与通勤共用通义问答，工作仅录音转写；无需助手名字。尚未实现语音抢话，不新增硬件命令。

## 开启与操作

1. 登录本地或远端后端，选择 Rise SDK 麦克风，在设备详情连接目标 Rise。
2. 确认耳机触控联动已开启（默认开启）；需要锁屏使用时，确认本次锁屏会话授权与前台服务有效。
3. 等当前连接至少一耳实际报告已佩戴，再等待“固件已确认开启”，然后操作耳机。未知或双耳未佩戴时显示等待，不立即发注册命令。设备页会显示实际事件计数与名称。“已确认开启”只证明注册成功，不代表每种手势已经实测。

佩戴门槛是 App 的产品策略，不是对固件 `status=6` 的解释，也不要求双耳同时佩戴。连接时的属性查询与触控等待共用一次 `refreshAuraPower`；当前连接最多主动查询一次，4秒仍未收到有效佩戴状态只更新等待说明，不判定硬件故障或重复发送命令。只有当前连接的 `ATTR_POSITION` 报告才可放行，旧连接数据、仅电量更新及未知值都不能代替。收到戴入报告后尝试一次注册；已经注册或命令处理中不会重复发送，失败后不会因戴入或切换开关而重试，仍需手动重新连接。已启用后摘下不反复关闭和注册监听，继续按下文暂停音频会话。

| 耳机实际事件与当前状态 | App 动作 |
| --- | --- |
| 单击 / 单捏，待机 | 生活/通勤开始 AI 通话；工作开始持续录音转写 |
| 单击 / 单捏，正在聆听 | 生活/通勤结束整场；工作停止、排空并提交所有待保存片段 |
| 单击 / 单捏，正在处理或轮次接续 | 结束整场，不再自动开麦；工作等待提交完成 |
| 单击 / 单捏，正在播放 AI 回复 | 停止播报并结束整场通话 |
| 单击 / 单捏，模式确认音播放中 | 停止确认音，明确接通常态对话 |
| 双击 / 双捏 | 生活 → 工作 → 通勤 → 生活；结束当前会话，工作先保存，AI 立即停播；目标模式待机 |
| 长按 / 长捏 | 与结束操作一致；工作先停止并保存 |
| 三击、三捏、短按、释放、滑动及未绑定事件 | 不执行 App 操作，不修改耳机的原有系统手势或固件设置 |

模式设置经后端确认后更新页面，可播放一次本地提示，提示后保持待机。生活与通勤无需称呼，每轮直接回复，回答后继续听。工作保存失败不切换，不显示已保存。迟到回调不能重新开麦。

只有设置更新收到明确的“上一项操作仍在进行”409拒绝时，才在同一后端、同一会话代次和可用会话内，按 0.5/1/1.5 秒最多延后三次；4秒窗口结束仍不成功就提示稍后再试。可用会话要求前台或显式锁屏授权仍有效。断网、超时或响应丢失不自动重发写请求；语音和 TTS 不参与此设置重试。

App 只接受当前目标设备、当前监听代次、固件确认后的事件；不会按设备名称推定支持。SDK 通过 `registerAuraTestEventListener` 开启 `0x560F` 事件流；接口同时包含头部事件，App 忽略头部/IMU和未知事件。SDK没有提供事件耳侧，不宣称区分左右耳手势。

单击与双击均等待400ms组合判定，双击覆盖待决单击。相同手势800ms去重、超过1500ms丢弃。已选择的结束/切换意图可跨自然轮次收尾；待机开始不能误作用于替代会话。执行时再次核验授权、登录、设备、手机通话和占用状态。

## 佩戴、连接和电量

- 戴好后提示一次就绪，单击接通；未知快照不会重复提示。左右耳都明确未佩戴时结束音频会话，并撤销本次锁屏授权；中间出现未知快照不会漏停，单耳取下或未知值本身不当作双耳摘下。双耳摘下时单击/双击不执行，重新戴上只提示就绪，不自动开麦。
- 断连、来电或音频焦点中断会停止相关录音/播放。纯文字请求仍可完成，后续播放另行核验路由。
- 已开启联动、App 在前台且非主动断开时，断连后只对原目标耳机按 2/5/10 秒延迟最多尝试三次。成功只恢复连接和触控监听；失败提示手动连接。离开前台、手动断开或关闭联动会取消自动重试。
- 左右耳电量只使用 SDK 实际上报值。≤20% 和 ≤10% 分级显示提醒，同级不重复刷屏；电量回升超过 25% 才重新提醒。未上报/无效值保持未知，不制造低电警报。
- 没有有效锁屏会话时，离开 App 停止采集和待接续，也关闭触控监听。通知权限可用时接通常态对话会建立前台服务；也可显式开启“本次锁屏耳机会话”。有效期间常态对话与已确认的触控可在锁屏继续，通知可挂断；持续通话会续期，仅空闲待命一小时过期。关闭任务/宿主销毁/Rise断连/来电撤销授权，不自动重启；独立定时与安静记录仍限前台。

## 联调与验收

在设备页查看 `controls`、`control_events`、`last_control`；SDK监听注册应答与真正手势事件分别记录。触控入口时间在 SDK 回调中立即采样，避免主线程延迟把旧事件当成新事件。

开启失败时保留首个 SDK 错误与固件数字 `status`，清理错误另外显示。SDK `2401` 表示测试监听忙；“正在反注册监听”可能是先前开启失败后的清理过程，不能据此推定耳机不支持或未佩戴。未获确认时不接收手势，重新连接后需重新取得开启确认。此接口的固件拒绝原因以真实返回及官方说明为准。

当前资料未提供 `0x560E status=6` 的具体语义。曾观察到单耳佩戴时注册确认成功，也观察到双耳未佩戴时返回该拒绝码；两次状态差异不能单独证明因果，佩戴等待策略的实物效果仍需验收。

实物验收顺序见 [当前三模式约定](mode-experience.md) 和 [交接](android-handoff.md)：无需称呼连续问答；听、想、播报时单击结束；工作超过60秒不中断，尾段保存；双击不误触单击、工作先保存、目标待机；再验证断连、摘下与来电。未实测项保持待验。

实际执行结果和构建标识统一记录在 [验收记录](acceptance.md)。
