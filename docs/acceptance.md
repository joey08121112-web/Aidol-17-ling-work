# 需求、实现与验收证据

验收范围保持最初的工作、通勤、生活三种模式与两条主链路。本表区分已实现代码、真实服务验证和仍需用户设备/权限的数据，避免把模拟演示当作真机成功。

更新日期：2026-10-17。服务测试是本轮开发时的结果，不保证未来配额、网络和账号状态。真实凭证仅留在本地配置，本文不含 Key。

默认交付形态为每位队友各自本地运行、各自耳机与 SQLite，Git `main` 协作代码。不包含公共服务器上线或频繁部署要求。

### 新增记忆功能：代码范围与待核对项

| 功能 | 当前代码范围 | 本节不等同于已通过的验收 |

## 最新：本机连续 stream 完整链路

执行入口：`python -m scripts.probe_e2e`，使用本机 `127.0.0.1:8000` 主应用，`SPEECH_ASR_MODE=stream`。公共测试句为「我喜欢清淡的食物，请推荐一份晚餐。」；先 TTS 合成，转换为与浏览器相同的 16 kHz 单声道 PCM16，以 40 ms 帧按实际速度送入 WebSocket。报告来源标记 `synthetic audio via live APIs`，没有采集用户麦克风。

| 检查点 | 本轮结果 |
| --- | --- |
| 会话 | ready 明确返回 `provider=cascade`、`asr_mode=stream`、`tts=true` |
| 输入识别 | **123500 字节** 16 kHz PCM，约 **3.86 秒**；ASR 准确识别完整测试句 |
| 文字交互 | `doubao-seed-2-1-turbo-260628`，`thinking=false`；回复「可以试试清炒时蔬配蒸蛋羹，再加一小碗杂粮粥呀，清淡养胃还舒服～」 |
| 音频输出 | 24 kHz PCM，累计 **357804 字节** |
| 数据 | `asr_persisted=true`；本地记忆快照总数 **10 条**，是包含之前测试的数据总量，不能当作本次新增量 |
| 错误 | `errors=[]` |
| 用时口径 | **11.687 秒**，从开始输入到完整输出接收结束，包含约 **3.86 秒**输入和全部合成音频接收；不是首包延迟、不是人耳实际播放完成时长 |
| 地图补充 | search HTTP 200 / 10 个 POI；walking 与 transit 均 available |
| 本地报告 | `artifacts/verification.json`，已被 Git 忽略，内容已更新为本次 stream 结果，重跑会覆盖 |
| 未覆盖 | Viaim 实际麦克风、蓝牙路由、浏览器播放音质、ANC 和物理按键 |

测试脚本会调用真实服务、产生费用，在本地库留下测试转写和记忆；结束时恢复其他设置并保留 `provider=cascade`。勿把合成音频链路成功当作耳机实物验收。

独立连续 ASR 检查还确认：保持 WebSocket 输入不断流时可收到 `definite:true` 的确定句子，不需要等连接结束才入库；一次测量在说话音频结束后约 **671 ms** 收到确定句子。这个数字是**单次观测**，不代表 SLA、普遍延迟或 ASR→文本→TTS 首包时间。

## 正常停止的尾句补充验证

连续 ASR 的正常停止另做了真实服务检查：按实时速率输入 **141246 字节**公共合成音频，说完立即发送 `stop`，不补静音等待。服务器准确返回并保存「本次会议确定明天完成耳机接口联调。」，无错误，收尾 **4281 ms**，结束后 `audio_clients=0`。记录位于本机被忽略的 `artifacts/stop-verification.json`。此检查证明服务器正常停止的 final 与持久化；前端停止、快速重启和旧回调隔离另由 Node 回归覆盖，不代替浏览器真机操作。
