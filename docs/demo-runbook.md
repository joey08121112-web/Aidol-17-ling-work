# 演示与故障排查

## 开场前

每位演示者运行自己的本地 Python 服务、连接自己的耳机，使用独立 `.env` 和 SQLite。无需等待服务器部署；下面步骤在本机完成，模型调用仍需要网络。

1. 插电、配对 Viaim，关闭其他占用麦克风的会议软件。
2. 启动主应用，确认 `/api/health` 正常。
3. 先验证真实模型会话，再授权浏览器麦克风；高德与硬件 SDK 状态单独说明。
4. 「偏好与设备」选择输入、输出，播放测试音。若配置 `APP_TOKEN`，先填写界面访问口令。
5. 导出需保留的数据，再按需清空旧演示记录。不要在录音期间清空。
6. 准备稳定网络和文字备用演示；`localhost` 必须在运行后端的同一台设备上访问。

当前凭证可选择两条音频路线：Qwen 原生实时用于自然低延迟对话；豆包 `cascade` 默认使用 ASR 2.0 连续识别、指定 Turbo 文本模型和独立 TTS。连续通道持续上传包括静音在内的音频，显示部分转写，供应商确定句子后处理记忆/回复。`SPEECH_ASR_MODE=flash` 才是 800 ms 静音切句的 HTTP 备用；不要把两种模式的测试时延混为一谈。

## 五分钟演示

### 0:00–0:45 架构与设备

展示耳机、设备选择与测试音。说明耳机负责采集/播放，Web 后端负责模型和业务，记忆可管理。ANC/按键若未接 SDK，直接展示待接入状态。

### 0:45–2:00 工作

打开自动切换，文本输入或真实说话：

> 开始会议，讨论需求。我负责前端，明天下午三点前完成耳机控制台。

另一位队友说：

> 我负责后端，周五前完成语音接口和记忆持久化。

再输入「嗯嗯，呃，好。」。展示模式理由、有效记忆、废话过滤。真实音频未做声纹分离，文字演示中的发言人是手工标签。工作模式不播放回答。

### 2:00–3:15 通勤

输入：

> 开始通勤，我正在坐地铁去公司。

然后输入模拟播报：

> 下一站即将到站，请提前做好下车准备。

展示到站草稿，点击复制或忽略；说明尚未发送给任何人。若高德已实测，填写真实目的地 GCJ-02 坐标并开启 GPS，展示标有「驾车路线估算」的结果，不将其讲成地铁车辆实时 ETA。

### 3:15–4:15 生活

输入：

> 结束会议，休息一下。我喜欢清淡的食物，不吃香菜。

再说「给我讲个笑话」。展示记忆如何进入后续对话。可切生活模式开启真实语音，验证耳机回放与开口打断。

轮询演示需先保存 `life_poll_enabled`，并勾选本次页面授权；默认每 5 分钟监听 30 秒，可为演示将间隔设为最低 60 秒。不能承诺在关闭页面后继续唤醒。

### 4:15–5:00 用户管理与边界

展示记忆搜索、删除、导出、个人偏好、手动模式覆盖。展示系统架构和事件；明确本轮已验证链路以及等待 SDK/交通数据/消息渠道的扩展点。

## 一键备用演示

点击「演示完整一天」。前端顺序提交工作、通勤、生活文本，全部标记 `source=demo`。流程临时打开自动模式，完成后恢复先前设置，但演示产生的数据会保留。它不能证明真实 ASR、TTS、GPS 或 SDK 已接通。

## 实时服务探测

在根目录执行（Windows）：

```powershell
./.venv/Scripts/python.exe -m scripts.probe_realtime --provider qwen --text-test
```

`session=true` 证明会话配置得到确认；`audio_bytes>0` 证明文本触发产生音频。该脚本不采集耳机麦克风、不播放音频，也不验证 ASR。Linux / macOS 替换为 `.venv/bin/python`。

完整级联验证使用 `python -m scripts.probe_e2e`，需先启动本机 8000 端口应用。它将公共测试句合成为音频，以浏览器相同的 PCM 帧通过真实 WebSocket 送入 ASR→Turbo→TTS，并检查记忆保存。脚本调用真实服务，会留下本地测试转写/记忆，结束时将 provider 保留为 cascade；结果写 `artifacts/verification.json`（不入 Git）。最新默认 stream 验收准确识别 123500 字节输入，返回 357804 字节 PCM、ASR 转写持久化、无 error。这不替代 Viaim 实物验收。

最新 stream 验收总用时 11.687 秒，包含约 3.86 秒输入及全部合成输出接收；它不是首包响应时间或耳机实际播放完成时间。独立 ASR 在音频结束后约 671 ms 返回 `definite:true` 是另一次单次观测，不能当作 SLA 或整链路首包时间。备用 flash 的历史结果另列于验收文档。

## 故障排查

| 现象 | 优先检查 | 处理 |
| --- | --- | --- |
| 页面打不开 | 服务终端是否启动、端口占用 | 运行 `run.py`，或修改 PORT 后重启 |
| Python 报时区错误 | 是否安装完整 requirements | 安装 `tzdata`，使用 IANA 时区 |
| 无设备/无法录音 | HTTPS/localhost、浏览器/系统权限 | 地址栏允许麦克风，刷新设备 |
| 有音量无转写 | 实际供应商、模型转写能力、网络 | 先探测服务，再看最终转写事件 |
| 有回复文字没声音 | 当前是否工作模式、输出设备、系统音量 | 切生活模式、测试音、系统路由 |
| Qwen 返回认证错误 | Key 是否属于比赛 MaaS、端点是否匹配 | 核对账号权限；不要直接套用 DashScope Key |
| 豆包返回认证错误 | 是否误用方舟文本或 ASR/TTS Key | 申请实时双工服务凭证或用 Qwen |
| 流式 ASR 返回 403 | `.env` 是否仍用旧资源名/端点 | 同步 `volc.seedasr.sauc.duration` + `bigmodel_async` 并重启；本轮原凭证已通过 ASR 2.0 连续识别 |
| TTS 返回 55000000 | TTS resource 与音色系列是否匹配 | 当前 mars 音色使用 `seed-tts-1.0`，不要搭配 `seed-tts-2.0` |
| cascade 无部分转写 | 当前 `asr_mode` 是否为 flash，端点/网络是否正常 | 默认改回 stream 并重启；flash 分段模式需停顿后识别 |
| 模型已配置仍失败 | 变量非空不代表有效，配置是否重启 | 跑探测，检查权限/配额/代理 |
| 文本清洗显示 fallback | 文本 Key/模型/根 URL、JSON 返回 | 修复文本服务；规则路径仍可演示 |
| 无高德 ETA | Key 权限、目的地坐标、是否通勤模式 | 填 GCJ-02 目的地并提供有效 GPS |
| 地铁 GPS 漂移 | 地下无可靠 GPS，当前非地铁数据源 | 使用播报提醒并标明限制 |
| 轮询没触发 | 开关、页面授权、可见性、模式、已有会话 | 满足条件后等待间隔；浏览器限制需用户手动开始 |
| ANC 未开启 | SDK 尚未接入 | 用耳机按键/官方 App，界面保持待接入 |
| 语音越来越慢 | 上行积压、网络、输出排队 | 停止重连，降低网络竞争，勿无限缓存 |
| 清空返回 409 | 音频会话尚在关闭 | 先停止，等待断开后再操作 |
| SSE 断开 | 网络或口令 | 界面会重试；重新取 state，而非等待历史事件重放 |

## 验证记录模板

```text
时间 / 分支 / 提交：
操作系统 / 浏览器：
耳机型号 / 固件：
模型 / 端点（不填 Key）：
通道：文字 / cascade / Qwen / 豆包原生实时
测试输入：
连接成功：是 / 否
最终转写：有 / 无
音频返回 / 实际耳机播放：
记忆入库 / 重启恢复：
模式与工作静音：
高德真实路线：已验证 / 未验证
SDK ANC / 按键：已验证 / 未提供
已知问题与复现步骤：
```

不要仅记录「跑通」。把 WebSocket 握手、模型音频返回、耳机播放、麦克风 ASR、记忆存储分别验收，后续队友就能直接定位哪一段需要继续接入。
