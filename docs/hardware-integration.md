# Viaim 耳机接入

厂商接口尚未提供。现在可验证的路线：Viaim 作为系统蓝牙音频设备，浏览器读取麦克风并播放模型语音。应用运行在 Web 与后端，不是安装到耳机固件。ANC、按键、电量、后台唤醒需厂商能力。

前期每位队友只连接自己的本地服务：耳机配对本机，浏览器访问本机 localhost，数据库和配置也在本机；无需云服务器。共享的是 Git 代码，不是耳机会话或个人记忆。

## 现有边界

`web/audio/hardware.js` 定义 `BrowserHeadset`，`AudioSession` 默认使用它。

| 方法 | 行为 |
| --- | --- |
| `capabilities()` | 输入、输出选择、ANC、按键、电量与传输方式能力标记 |
| `devices(requestPermission)` | 可先申请权限，再枚举系统设备 |
| `capture(deviceId)` | 返回单声道 `MediaStream`，请求回声消除、浏览器降噪和自动增益 |
| `setOutput(context, deviceId)` | 使用 `AudioContext.setSinkId`；不支持且指定了设备时提示到系统设置选择，未指定设备时使用系统默认输出 |
| `setNoiseCancellation()` | 当前抛出等待 SDK 错误，不模拟成功 |

`ViaimSDKAdapter` 仅保存 SDK 对象并标记 `viaim-sdk-pending`。还需要完成 SDK 映射、握手和 `AudioSession` 的适配器选择，不能只新增类就宣称已经接入。

## 真机验收步骤

1. 系统蓝牙配对 Viaim，确认输入与输出均指向耳机。
2. Chrome / Edge 打开 `http://localhost:8000`；远程访问使用 HTTPS。
3. 「偏好与设备」→「授权并刷新音频设备」，明确选择 Viaim 输入、输出。
4. 「播放测试音」，确认来自耳机；不支持输出选择时，在系统声音设置选择 Viaim 默认输出。
5. 选择 Qwen 原生实时，或配置齐全的豆包流水线 `cascade`，手动切生活模式，再点击「开始聆听」。cascade 默认持续 ASR，部分转写先显示，最终句子进入模型和 TTS；只有 `SPEECH_ASR_MODE=flash` 备用模式先在本地静音切句。
6. 分别验证音量、最终转写、语音回放、记忆保存。
7. 工作模式验证只记录、不播放；停止后确认麦克风指示灯关闭。
8. 断开耳机验证停止与提示；重新配对后刷新设备并开始新会话。

蓝牙 HFP/HSP 双向通话可能降低播放音质，部分系统启用耳机麦克风后自动改变路由。耳机拾音通常针对佩戴者优化，多人会议效果须现场测试。浏览器设备名和 `deviceId` 不是可靠设备身份认证。

Web Bluetooth 不保证能直接读取蓝牙耳机麦克风。常规音频来自系统音频设备，BLE 控制通道与音频通道通常独立。

## SDK 实施顺序

1. 厂商最小 Demo 先验证握手和音频，记录设备及固件版本。
2. `ViaimSDKAdapter` 实现能力探测，仅在真实支持且握手成功时标记 ANC/按键/电量可用。
3. SDK 返回 `MediaStream` 时复用 AudioWorklet；返回 PCM 回调时增加输入适配，统一单声道 16 kHz PCM16 后复用 WebSocket。
4. 输出接收 24 kHz PCM16，按 SDK 要求转换，防止浏览器与 SDK 双重播放。
5. 模式切换时请求 ANC，回显实际结果；失败不阻断音频。
6. 按键与佩戴事件复用统一 `start/stop` 生命周期。
7. 完成解除订阅、页面退出、断连、重连、快速启停的资源处理。

| 验收场景 | 预期 |
| --- | --- |
| 输入输出 | Viaim 实际拾音、转写、回放成功 |
| 工作模式 | 记录收到的发言、不播放，多人拾音限制有记录 |
| ANC | 设置后读取状态一致，失败可解释 |
| 打断 | 开口后本地播放停止，上游回合继续可用 |
| 断连 | 释放麦克风和服务会话，界面不假显示连接 |
| 重连 | 无重复采集、重复回调和双重播放 |
| 后台 | 页面隐藏、锁屏、关闭时的行为有真实记录 |

`noiseSuppression=true` 是浏览器约束，不是 ANC。VAD 不理解唤醒词，必须先开启录音。语音回到耳机不代表模型运行在耳机；当前页面关闭后不能持续监听。
